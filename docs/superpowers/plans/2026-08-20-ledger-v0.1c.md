# Ledger v0.1c Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make both deferred questions answerable, then answer them — settle `time_cluster` against its pre-registered 0.70, and settle whether the service axis has earned a confidence claim against 0.95.

**Architecture:** Six tasks. The inverse memo hazard makes service precision falsifiable for the first time; a `service_confidence_verdict()` mirrors the existing `time_cluster_verdict()` so both decisions are computed rather than narrated; three staged measurements attribute each dataset change to its cause; then two tasks apply the criteria and act, each with both branches specified.

**Tech Stack:** Python 3.13+, stdlib only, `pytest` as the sole dev dependency, `uv` for environment management.

**Spec:** `docs/superpowers/specs/2026-08-20-ledger-v0.1c-design.md`

## Global Constraints

- **Python:** `requires-python = ">=3.13"`. Runtime dependencies MUST remain empty — stdlib only. `pytest` is dev-only.
- **Money:** amounts are ALWAYS integers in micro-USDC. Never a float. A refund is a positive amount with `tx_type='refund'`.
- **Timestamps:** ISO 8601 UTC, `YYYY-MM-DDTHH:MM:SSZ`, zero-padded, stored as TEXT.
- **No tax advice:** no user-facing string may advise on tax or accounting treatment.
- **Pre-registered and immovable:** `TIME_CLUSTER_THRESHOLD = 0.70`, `CALIBRATION_THRESHOLD = 0.95`, `MIN_VERDICT_SAMPLE = 20`. No value changes in this release.
- **The criteria bind.** Once the evidence exists, the thresholds decide. Do not defer either decision, and do not adjust anything to influence which way one lands.
- **Confidence is per-axis.** If the service axis earns confidence, its money must NOT join the payer axis's "Confidently identified" total.
- **Existing tests:** 192 currently pass. Any change to one must be a deliberate, justified correction recorded in the task report — never a threshold quietly loosened.

### Task 1: The inverse memo hazard

Makes service precision falsifiable. Every existing generator derives `service_truth` from the memo, so memo and service agree by construction; the only divergence is memo-drift, which fragments and costs recall. This hazard causes a *merge*, which is the only thing B-cubed precision penalizes.

**Files:**
- Modify: `src/ledger/simulate.py`
- Test: `tests/test_simulate.py`

**Interfaces:**
- Consumes: `UNGROUPABLE`, `TX_TYPE_PAYMENT` from `ledger.models`
- Produces:
  - `HAZARD_SHARED_MEMO_DIFFERENT_SERVICES = "shared_memo_different_services"`
  - `HazardConfig.shared_memo_different_services: int = 8`

**Why the senders repeat, and why the services are new.** Two design choices make this hazard's effect attributable:

*Repeating senders* mean `sender_match` claims these transactions confidently on the payer axis, so the hazard is **payer-axis-neutral** and cannot perturb `time_cluster` — the very rule Task 4 decides. One-off senders would have landed in `time_cluster`/`none` and confounded the staged measurement.

*New service names* (`premium-weather`, `premium-llm`, used nowhere else) keep the damage to precision only. Reusing an existing service like `weather-api` would enlarge that service's true group and depress the *recall* of the 21 existing `weather-api` transactions — spreading the hazard's effect across unrelated rows.

**Sizing is chosen for comparability, not for outcome.** Existing hazards are sized 6, 6, 8, and 22. `8` sits squarely among them. **This matters more than it looks:** at 97 existing `memo_match` payments, the resulting precision is `(97 + 8×0.5)/105 = 0.962`, which passes 0.95 — but `N=12` yields 0.945, which fails. The size determines the verdict. It is therefore fixed on comparability grounds and must not be adjusted after seeing where the number lands. Task 3 records the sensitivity explicitly.

**Why a verdict function rather than prose.** `time_cluster` already prints `PASSES`/`FAILS` computed against its constant, precisely so the result cannot be walked back once known. A decision this release exists to make must not arrive as a sentence a human wrote after looking at a number. The service decision gets identical machinery.

Note the return shape differs from `time_cluster_verdict`, which returns `(precision, passes)` and makes its caller re-derive the count by scanning `per_rule`. Returning the count here avoids that second scan.

```python
def service_confidence_verdict(
    result: EvaluationResult,
) -> tuple[float, int, bool] | None:
    """Apply the pre-registered service criterion. None when memo_match never fired.

    Returns (measured B-cubed precision, firing count, whether it earns a
    confidence claim).

    The criterion reuses CALIBRATION_THRESHOLD rather than inventing a number:
    a rule that could not survive the floor it would then be subject to has no
    business claiming confidence in the first place. Withholds below
    MIN_VERDICT_SAMPLE for the same reason time_cluster does - a precision
    computed over a handful of rows is a coin flip, and withholding can only
    ever deny a claim, never manufacture one.
    """
    for metrics in result.per_rule:
        if metrics.rule == RULE_MEMO_MATCH:
            earns = (
                metrics.count >= MIN_VERDICT_SAMPLE
                and metrics.precision >= CALIBRATION_THRESHOLD
            )
            return metrics.precision, metrics.count, earns
    return None
```
